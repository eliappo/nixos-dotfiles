# CLAUDE.md

NixOS + home-manager flake driving **3 machines** from one repo. Read this before working — it
captures the architecture, conventions, and rebuild/commit workflow so you don't have to
re-discover them.

## Overview

One flake, built with **flake-parts** + **import-tree**. `import-tree ./modules` auto-discovers
every `.nix` under `modules/`, so `flake.nix` never changes when adding hosts. `modules/` holds
**only hosts**; the shared system/home modules live in `nixos/` and `home/` and are pulled in by
each host via relative path.

Three hosts:

| hostname        | role    | machine | gaming |
|-----------------|---------|---------|--------|
| `nixos-desktop` | desktop | nvidia + rtl8812au wifi dongle | yes (gamescope, TV `HDMI-A-1`) |
| `nixos-virgin`  | laptop  | nvidia + power mgmt | no (steam only) |
| `nixos-nas`     | server  | disko disk, static IP `192.168.10.101` | no |

## Layout

| path | what |
|------|------|
| `flake.nix` | entry: `flake-parts.lib.mkFlake` + `import-tree ./modules`. Inputs: nixpkgs `nixos-25.05`, home-manager + stylix (`release-25.05`), claude-code + niri (unstable), flake-parts, import-tree, disko |
| `modules/hosts/<h>/default.nix` | per-host flake-parts module registering `flake.nixosConfigurations.<name>` |
| `modules/hosts/<h>/_hardware-configuration.nix` | auto-generated by `nixos-generate-config` — **never hand-edit** |
| `modules/hosts/nas/_disk-config.nix` | disko partition layout (nas only) |
| `nixos/default.nix` | aggregates all shared **system** modules (desktop/laptop) |
| `nixos/server.nix` | trimmed system set for the nas (+ ssh-server, git-server, fileshare) |
| `nixos/<feature>.nix` | one system concern each (core, boot, networking, users, hardware, desktop, gaming, nvidia, …) |
| `home/default.nix` | aggregates all shared **home-manager** modules (desktop/laptop) |
| `home/<feature>.nix` | one home concern each (terminal, development, desktop, waybar, media, tools, ssh, theming, base) |
| `config/<app>/` | raw dotfiles (alacritty, hypr, niri, nvim, qtile, rofi, kanata, waybar) — live-symlinked |
| `scripts.nix` | custom shell scripts, consumed by `home/tools.nix` |
| `/home/elias/secrets.nix` | **outside the repo**; imported by `nixos/networking.nix` (wifi pw, tokens) |
| `_draft/` | proposed dendritic rewrite — **not live**, see note at bottom |

## How it wires together

```
flake.nix
 └─ import-tree ./modules  ──▶ modules/hosts/<h>/default.nix   (each a flake-parts module)
       └─ nixpkgs.lib.nixosSystem { specialArgs = { inherit inputs; }; modules = [
            ./_hardware-configuration.nix
            ../../../nixos/default.nix        # or nixos/server.nix (nas)
            { <host overrides>; home-manager.users.elias.imports = [ ../../../home/default.nix ]; }
          ]; }
```

- `nixos/default.nix` imports the home-manager + stylix nixos modules, then every `nixos/*.nix`.
- Machine-specific features are **opt-in** under the `custom.*` namespace via `lib.mkEnableOption`:
  `custom.gaming`, `custom.nvidia`, `custom.rtl8812au`, `custom.syncthing`, `custom.git-server`,
  `custom.fileshare`. The shared module declares the option + config; the host flips it on.
  Example (desktop): `custom.gaming.enable = true; custom.gaming.tvOutput = "HDMI-A-1";`.
- `import-tree` **excludes any path starting with `_`** — that's why `_hardware-configuration.nix`
  and `_disk-config.nix` live under `modules/` without being auto-imported as flake modules.
- Per-host branching inside home-manager reads `osConfig.networking.hostName` (e.g.
  `home/desktop.nix` picks the right `config/hypr/monitors-*.conf`) — no `extraSpecialArgs` threading.

## Conventions

- **New shared system feature** → add `nixos/<feature>.nix`, then list it in `nixos/default.nix`
  (and `nixos/server.nix` if the nas needs it).
- **New shared home feature** → add `home/<feature>.nix`, then list it in `home/default.nix`.
- **Machine-specific feature** → gate it behind a `custom.*` `mkEnableOption` and enable per-host in
  `modules/hosts/<h>/default.nix`. Don't hardcode one machine's needs into a shared module.
- **Never edit** `_hardware-configuration.nix` — regenerate with `nixos-generate-config` if hardware
  changes.
- **Dotfile tweaks** in `config/` (alacritty, hypr, nvim, niri, rofi, kanata…) are
  `mkOutOfStoreSymlink`ed by `home/desktop.nix` → changes are **live, no rebuild needed**. Only
  rebuild when you change the nix that defines the symlink/service. (Stylix owns alacritty theming;
  kanata config paths are injected into systemd units.)
- Commits: conventional-commit style, scoped, matching existing log — `feat(nas): …`,
  `fix(desktop): …`. Branch off `main` for anything non-trivial.

## Workflow

```bash
# 1. evaluate before switching
nix flake check                              # evaluates ALL hosts — catches eval errors
nixos-rebuild build --flake .#nixos-desktop  # build one host without activating

# 2. apply (run ON the target machine; needs sudo)
sudo nixos-rebuild switch --flake .#nixos-desktop   # or .#nixos-virgin / .#nixos-nas
sudo nixos-rebuild test  --flake .#<host>           # trial: active now, reverts on reboot

# 3. inputs (deliberate, commit the flake.lock change)
nix flake update                             # bump all inputs
nix flake lock --update-input nixpkgs        # bump one

# pure config/ dotfile edit → just save, it's live. No rebuild.
```

Rebuilds run per-machine, so test a given host's change on that host. `nix flake check` is the
fast cross-host sanity gate you can run anywhere.

## Gotchas

- `/home/elias/secrets.nix` is required and **not in the repo** — a fresh clone won't evaluate
  until it exists.
- Mixed channels: system is stable `25.05`; `claude-code` and `niri` track unstable.
- The nas is special: `nixos/server.nix` (not `default.nix`), disko-managed disk, minimal home
  (`base.nix` + `ssh.nix` only), reachable as `nixos-nas.local` (avahi) and over zerotier.
- Compositors: both Hyprland and Niri are enabled (`nixos/desktop.nix`). Hyprland bundles its own
  XWayland; Niri does not — it needs `xwayland-satellite` on PATH (installed in `nixos/desktop.nix`)
  to run X11 apps/games like Steam. The `game-console` TV kiosk (`nixos/gaming.nix`) is
  **Hyprland-coupled** (`hyprctl` + nested gamescope) — known structural wart; revisit if Niri
  becomes the primary session.

## `_draft/` — future option, not live

`_draft/` is an in-progress "dendritic" rewrite: every feature co-located in a single file with
both its NixOS and home-manager halves, staged through `flake.modules.nixos.*` /
`flake.modules.homeManager.*` and collected per-host via `builtins.attrValues`. It's partial /
educational and **not wired into the live build**. If revisiting the architecture, start with
`_draft/README.md` and `_draft/COMPARISON.md`. Until then, the layout documented above is canonical.
